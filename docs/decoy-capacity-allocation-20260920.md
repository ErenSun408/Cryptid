# FAT32 外层卷安全空间与受控写入：实测结论

本报告合并 2026-09-20 的分配反例、重试、指定簇、多段和顺序填空洞实验。保留可复验的方法、关键结论与限制；逐次 CSV、旧报告和本机二进制摘要仅存于本地 out/experiments，不作为仓库交付。后续第一片故障恢复结论见文末补充。

## 结论与已验证范围

普通复制不能保证利用保护区前的空闲；受控流程“规划安全簇 → 预分配 → 保留正确位置／搬移其余部分 → 核验全部位置 → 写入并刷新”在本次 FAT32 样本中可以利用不连续空闲，且不需要先整理已有文件。安全空闲可以作为当前空间事实，仍不能承诺任意文件都能成功上传对应字节数。

环境为 Windows 10.0.26200.0、VeraCrypt 驱动文件版本 1.26.29.3；簇大小 1024 字节。所有容器均为 out 下新建的一次性样本，挂载始终启用隐藏保护，没有操作真实卡或用户原容器。128/64 MiB 表示容器／隐藏卷创建参数，不等于实际保护长度；真实边界由候选 DLL 解密卷头取得。

| 实验 | 样本与操作 | 关键结果 |
|---|---|---|
| 普通分配 | FAT16 32/16 MiB、FAT32 128/64 MiB；空卷、删除前半批／交错删除、重挂、追加；两轮共 48 组 | FAT32 交错删除释放 24 MiB 后，仅新增 14.75 MiB 即触发，前方仍至少 23.97 MiB 空闲；重挂不能解决 |
| 触发后重试 | 首轮 36 次，第二轮 48 次；每轮三个独立基线，各重试从基线复制 | 同挂载及重挂后新增 4 KiB、64 KiB、1／4／16／23 MiB 均失败；删除失败文件后新增 4 KiB／1／23 MiB 也失败；覆盖已有 1 MiB 文件 3/3 成功且重挂持久 |
| 指定单段 | 两种准备方式：FileAllocationInfo 后设置 EOF、直接设置 EOF；4 KiB／1 MiB，各两份基线 | 最终管理员 8 组全部成功；最大安全段 1 MiB，搬移、写入、重挂校验通过 |
| 多段文件 | 两种准备方式、两份基线，8 MiB 文件 | 四组均分别占用八段 1 MiB 空洞，重挂内容正确；每组 25 个原文件名称／长度／内容摘要未变 |
| 顺序填空洞 | 实际构造 1／2／3／4／5 MiB 五段；一轮连续挂载，一轮每文件重挂 | 8 MiB 使用 1+2+3+2；下一份 3 MiB 使用 2+1；下一份 4 MiB 使用第五段余量。两轮均通过 |
| 安全空间耗尽 | 顺序实验五段以外另有 15,446,016 字节安全空闲 | 两轮均写完该部分，安全空闲归零；超出余量一簇以及归零后 4 KiB 请求均在创建前拒绝，文件集合和空间未变 |

所有完成的实验在卸载后比较整个隐藏保护区域的 SHA-256，结果与基线一致；这不代替全文件系统一致性检查。成功上传须通过刷新及重挂后内容校验，多段／顺序实验采用随偏移变化的图案检测错序。顺序实验每轮四个新文件重挂校验通过，33 个原文件名称／长度／内容摘要未变，未观察到保护触发。

## 度量口径与重要实现条件

- 最初 48 组未获管理员位图授权，采用保守下限证明反例：文件系统空闲减去“保护起点至外层结束区域向上簇对齐、再加一簇”的上界，截断至零。该结果不是精确安全空闲，不作为产品算法。
- 重试样本重挂前空闲下限约 23.98 MiB，重挂后约 22.67 MiB；不能据此说 23 MiB 严格小于剩余额度，更小文件失败足以构成反例。
- 后续指定位置、多段与顺序实验取得新的 UAC 授权，使用完整位图、FAT BPB 和系统簇计数交叉验证；目标簇必须完整位于保护起点之前。普通权限只能完成预分配，不能算搬移通过。
- 位图是瞬时状态，每次搬移前重查。预分配可能已经占到计划中的安全位置，这部分应保留；只扫描空闲会漏掉本文件自己的正确分配。
- 预留分配空间与设置文件长度不是同一件事；本实验在读取簇位置及搬移前明确设置 EOF。全部位置通过核验后才写入内容，空间不足在创建文件前拒绝。
- 原有文件不需要预先搬动。文件可以跨多个安全空洞，但不能用普通 WriteFile 的偏移指定物理位置，也不故意以触发隐藏保护作为正常满额出口。

## 失败记录与尚未证明的部分

最初完整位图授权被取消，未绕过；后来在新授权下执行。单段初期两次因零长度文件簇查询遇到 EOF 提前退出，补齐 EOF 后八组通过。顺序实验首次忽略预分配已占的正确位置，第三文件位置断言失败；加入“保留正确分配”后两轮通过。提前退出不计入完成，失败样本保留在本地；相关隐藏区摘要另行复核一致。

/W4 /WX 构建、输出目录拒绝覆盖、补丁格式及结束后的挂载清理检查通过。没有运行与实验无关的全套回归，没有改变正式上传、页面、正式依赖 DLL 或安装包。

尚未证明：部分搬移／写入失败回滚、取消、进程或整机中断、并发目标占用、外部整理再次搬移文件、目录增长、非整簇文件、GiB 文件、不同簇大小、NTFS／exFAT、一般目录树及全部元数据。已有文件核对不包括 ACL／时间戳。普通复制与管理员受控写入不是同轮随机配对实验，不能给出通用成功率。元数据和簇对齐开销仍会使“安全空闲”不同于文件负载额度。

## 复验入口与产品边界

测试源码为 tests/decoy_allocation_behavior_tests.cpp，CMake 目标 decoy_allocation_behavior_tests；仅开启 USB_VAULT_ENABLE_INTEGRATION_TESTS 后可显式构建，EXCLUDE_FROM_ALL，未注册自动 CTest。候选 FormatDLL 的构建及只读几何 ABI 见 third_party/veracrypt_format/README.md。测试口令固定且仅用于样本，不接受真实用户凭据。

| 显式模式 | 所需参数与用途 |
|---|---|
| --new-disposable-run-basic | 候选 DLL 绝对路径、新输出目录：创建基础样本与普通分配实验 |
| --new-disposable-run | 同上，管理员完整位图模式；不能将首次取消算执行通过 |
| --recover-disposable-run | 候选 DLL、完成的基础实验目录、新目录：重试与覆盖对照 |
| --placement-disposable-run | 候选 DLL、完成的 recovery 目录、新目录：指定单段 |
| --multirun-disposable-run | 同上：多段 8 MiB 文件 |
| --sequential-disposable-run | 候选 DLL、完成的基础实验目录、新目录：不同空洞连续填充及耗尽 |

输出目录必须不存在；每次只复制并挂载自己的测试容器，显式管理员请求应由操作者批准。不要在真实容器上使用夹具。每轮自行产生结果、完整性断言及完成标记，失败记录不覆盖既有目录。

用户已选择 FAT32 作为下一阶段路线。测试夹具只是证据，正式功能必须另行实现认证会话绑定、受限提权边界、目标身份校验、失败收束和空间刷新；需求 8.6 的敏感几何／身份不落盘约束不变。本提交未宣称 P3.25.9 或产品功能完成。

## 第一片补充：失败与恢复边界

六个 FAT32 128 MiB 独立副本的故障实验完成，所有场景清理并重挂后，原有 25 个文件名称／长度／内容摘要未变，安全空闲均恢复为 25,100,288 字节，整个隐藏保护区摘要一致。原始结果仅本地保存，最终目录由 out/fault-admin-active.txt 指向。

| 故障 | 验证结果 |
|---|---|
| 只读句柄预分配 | 错误 5，清理并重挂后无残留 |
| 搬完两段后取消 | 删除本次目标后，重挂文件集合及空间恢复 |
| 目标先被另一测试文件占用 | 搬移错误 87，目标内容保留；关闭／清理阶段观察到保护触发，重挂核验后恢复 |
| 全部搬移后写入 64 KiB，再用只读句柄写入 | 第二次写入错误 5，清理后恢复；这是权限故障，不是介质错误模拟 |
| 故意向尚在保护区的预分配文件写入 | 错误 87、保护触发；删除虽返回成功，重挂后文件仍在，再次删除并核验后恢复 |
| 部分搬移后的进程终止 | 子进程仅接收父进程继承的已打开测试句柄，TerminateProcess 自身退出码 99；观察到保护触发，重挂后 8 MiB 部分文件仍在，按本轮已知身份清理后恢复 |

正式实现必须保留原始错误、停止被保护阻止的上传队列，并将“清理接口返回成功”与“重挂后确认清理持久”区分。进程终止后无法仅靠内存证明旧临时文件归属，不得仅凭文件名自动删除它；保留可见的未完成文件供用户核对，不新增泄露维护身份／隐藏布局的恢复日志。只清理本次独占创建并持有身份的目标，原有同名文件不得删除。

最终 /W4 /WX 构建、六场景、输出目录防覆盖、无效子句柄拒绝、挂载收束检查通过。早期一次错误假定最前空洞足够大，另一次按路径打开／写入的子进程超时；修正为选足够大的空洞、继承已打开句柄后完成，失败轮次未计为通过。后台保护触发的观察时点不等于唯一底层原因。

本片没有模拟整机断电、真正介质写错、删除权限失败、随机压力或任意写入瞬间崩溃；进程终止发生在部分分配阶段，部分数据写入故障由另一场景覆盖。此为恢复策略证据，生产级上传和恢复尚待后续切片实现。
