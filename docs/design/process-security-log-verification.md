# 2011 细分诊断验证（当前）

日期：2026-09-22。当前共 114 个固定步骤，详细定义见 [编号表](startup-failure-codes.md)。下方 89 步／819 场景报告仅保留为本日先前实现的历史证据。

## 实现与结论

- 当前源码产生 2011 的出口全部有步骤：本地主进程经固定编号异常，helper 环境拒绝经协议 v14 的专用 security_step 字段；源码和编号表核对无缺号。
- 90–106 区分环境格式、未知变量、大小写、重复、三个必需变量缺失／空值、TEMP/TMP 关系及 SystemRoot/WINDIR 条件；107–108 区分获取／释放环境块 API 失败。
- 109–114 拆开空 SID、无效 SID、完整性 SID 缺少子授权项；旧编号 35 仅用于 SID 不匹配，43 用于无效完整性 SID，44 用于完整性级别过高，52 用于 profile API HRESULT 失败。
- 协议从 v13/56 字节响应升级为 v14/60 字节响应。仅接纳 helper 的 90–108 步，要求原因和底层类别匹配；零步骤、未知步骤、冒用本地步骤、成功附错、跨阶段步骤和旧版本均拒绝。

## 安全审查与剩余限制

- 环境校验不分配字符串副本，借用视图仅在 OS 环境块有效时使用；释放后只保留固定数值。首错顺序固定，不采集变量实际名称／值、路径、SID、令牌或权限位图。
- 只允许严格白名单和唯一变量；新实现明确拒绝旧实现可能接受的重复／异常组合，不放宽安全边界。日志及鉴权不自动重试，不访问真实卡。
- 编号定位首个失败检查；拒绝访问等 Windows 错误不能独自证明杀毒软件、策略或具体外部软件责任。环境拒绝与释放环境块同时失败时保留前者，当前 IPC 不返回这项次生释放错误。
- 其他本地 Windows API 仍未逐项强制失败；其异常捕获／日志矩阵及源码审计通过，不等于全部真实 API 故障已复现。
- 首次页面就绪之后的新错误仍不在启动日志范围；磁盘／权限写入失败、进程强杀／崩溃及入口前失败不保证日志完整。
- 用户电脑原 2011 尚未复现。旧日志不能回补，新主程序与 helper 必须成套交付；本轮尚未打包或安装。

## 结论与范围

已审计当前源码的 89 个本地主进程安全步骤，全部有编号对应；另有 helper 环境校验失败通过 IPC 返回 process_security，当前协议不包含安全步骤字段。新增模拟测试验证从异常、清理错误保留、卡入口捕获到 UTF-8 日志输出的链路，91 类诊断 × 3 个记录时点 × 3 种清理组合 = 819 场景全部通过。不能据此声称所有 Windows API 或设备故障已被实际触发。

## 未覆盖及解释限制

- 模拟入口为卡检查源抛出的诊断异常，未逐个替换真实 Windows API 返回值；API 到诊断的编号、类别和即时 GetLastError 通过源码审计核对。
- 没有注入真实 WM_DEVICECHANGE、定时器或 WebView 回调；模拟其诊断记录时点，生产接线沿用上一片的代码审查和应用构建证据。
- helper 环境拒绝可记录到类别级原因，但不能区分其中每个环境检查条件；当前协议没有该步骤字段，测试不伪造步骤。
- 写入权限／磁盘错误、强杀及进程崩溃不能保证日志完整；运行期（首次页面就绪后）的新错误仍不在启动日志范围。
- 未操作实卡、未复现用户机器的 2011、未执行全量测试；本轮只增加测试和文档，没有修改进程隔离规则或 helper 协议。
