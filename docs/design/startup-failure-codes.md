# 应用启动失败审计与数字错误码对照表

审计日期：2026-09-20。代码基线：`a0686c6`。

本文件包含**设计与源码审计结果，不代表全部错误码已经接入产品**。范围覆盖 Windows 拉起 EXE、应用前置检查、原生会话构建、WebView/页面就绪、首次插卡探测，以及配置返回和拔插后的重新探测；登录密码验证、建卷、挂载等用户操作不展开。下文“现状/当前实现/缺口”保留审计基线描述，后续完成情况以本节状态为准。

2026-09-20 接入状态：`b5c73cb` 已实现单次入口数字诊断、路由失败与原始/清理失败分别保存，`da82c49` 已补 API Key/PIN 阶段。第三片已接入页面只读诊断显示、WebView 原生数字提示、导航完成/进程失败及页面就绪检查、30 秒界面超时和过期回调隔离。只输出固定数字，不记录后台操作日志，也不增加认证重试。

尚未实现本表全部 10xx/11xx 前置检查细分、完整崩溃报告、日志导出、每个底层 SDK 出口的细分，以及真实故障的逐项注入。第三片导航失败已能提示 1313，但尚不显示 WebErrorStatus 细分；进程失败提示 1314，尚不细分 ProcessFailedKind。原始错误/首个附加清理错误固定容量保存，更多嵌套清理错误不组成无限链。首次启动实机问题仍需用新包取得实际数字码，不能将诊断接入称为根因已修复。

“全面”指检查当前实现的主要失败出口及诊断缺口，不能枚举 Windows、驱动和第三方 SDK 的所有内部故障。某阶段失败只能确定失败边界，不能直接推断杀毒拦截、网络故障、卡损坏或密码错误。

## 1. 实际启动顺序

1. Windows/安装器/快捷方式启动主 EXE。进入 `wWinMain` 前失败时，应用无法显示自己的错误页。
2. 解析 EXE 所在目录，检查 `.usb-vault-update` 和 `.usb-vault-setup.lock`。存在或不能确认不存在，均拒绝启动。
3. `OleInitialize`；无显式开发参数时执行 `inspect_startup()`：系统架构、六类随包文件、WebView2、VeraCrypt 驱动、已保存凭据。
4. 前四项不通过则退出；凭据不就绪则进入配置页。**这一步不访问卡，也不验证保存的 PIN 是否正确。**
5. 注册/创建窗口，恢复窗口大小，注册拖放；拖放失败目前只告警，其他功能继续。
6. 固定页面文件；正常会话分支构造卷服务、卡适配器、入口/认证/界面控制器，注册 HID 通知并枚举已插入卡。
7. 有卡时立即执行一次 `handle_arrival()`：读取凭据 → 校验/准备 helper 与 SDK → 建立隔离进程与 IPC → SDK 认证并只读探测卡 → 校验响应/退出/清理 → 决定卡入口。
8. **步骤 7 在 WebView 初始化和主窗口显示之前同步执行。** 此处访问卡，错误 PIN 可能消耗卡的尝试次数。前置检查“不访问卡”不能扩展解释为整个应用启动不访问卡。
9. 异步创建 WebView 环境与控制器、配置安全选项、挂原生桥、导航本地页面；注册卡事件定时器并进入消息循环。
10. 页面读取启动视图、窗口预设、会话状态和活动会话。无卡/待初始化/待登录是正常结果；不可用或桥失败才是故障。配置页返回和真实拔出后重插会重新建立/探测入口。

安装完成页此前继承 TEMP，快捷方式此前指向已删除的事务暂存目录；`a0686c6` 已修正。**尚未证明该差异就是首次卡探测失败的根因。** helper 自身采用显式绝对路径、独立工作目录和裁剪后的环境，不宜只凭主进程工作目录推断 SDK 出错。

## 2. 数字码规则

- 页面只显示十进制四位主错误码，例如 **2019**，配中文原因和对应处理建议。`0000` 表示无错误，不把正常无卡或待配置计为故障。
- 主码分区：10xx 启动前/入口，11xx 前置检查，12xx 原生会话，13xx WebView，14xx 页面/桥，15xx 设备事件，20xx 已有诊断阶段，30xx 缺少阶段时的卡错误，40xx 入口/记录判定，90xx 未分类故障。
- 主码优先选择实际失败的、可证实的最具体阶段。已有 `DiagnosticStage = n` 映射到 `2000+n`，**不更改原有枚举或 helper 协议数值**。无阶段但存在 `CardError = n` 时用 `3000+n`。明确的本地步骤另用本表代码。
- 同时保留独立的数字字段：`reason`（现有 CardError 1～18，0 表示无可用卡错误）、`native_kind`（0 无、1 Win32、2 HRESULT、3 进程退出码）、`native_code`（无符号 32 位十进制）。类别不是卡错误时不得把同值的系统错误冒充 CardError。
- 示例：主码 **2019**、原因 **18**、底层类别 **0**、底层码 **0**，只表示等待辅助进程响应超时；不能解释为 PIN 错误或已经确认网络故障。底层码 0 在类别 0 时表示**未取得**，不是操作成功。
- HRESULT 如需内部十六进制转换，应在诊断工具中进行；用户页面及导出的编号仍用数字。未知阶段/原因不得误解成成功；本地归为 9001，非法 IPC 枚举仍按 2018 拒绝。
- 一个失败事件保留一个主码；清理也失败时额外保留 `cleanup_code`，不能丢弃原始失败。当前实现尚未完整做到这一点。
- 表中“现状”描述当前观测能力；**本表所有四位主码都是拟接入的新显示编号**。同一主码可覆盖数个技术上同类的失败出口，底层码与步骤编号用于进一步区分。

## 3. Windows 入口与前置检查

| 主码 | 条件/失败可能性 | 当前实现/诊断缺口 | 处理与边界 |
|---|---|---|---|
| 1001 | EXE 未能由 Windows 启动：目标缺失、拒绝访问、映像/架构不支持等 | 主应用尚未运行；安装完成页 `Exec` 未检查结果；不能由应用自行记录 | 启动器捕获失败后才可给出本码；不能仅凭没有窗口断言是哪一种原因 |
| 1002 | 无法取得主模块路径、路径截断或不能提取父目录 | 首轮捕获为“无法确认安装状态”；后续调用可能并入界面初始化错误 | 保留具体 API 和系统码；不导出用户完整路径 |
| 1003 | 存在安装锁或更新事务条目 | bool 检查统一显示维护提示，未区分正在维护与遗留条目 | 等待维护结束；中断更新使用对应安装包恢复，不自动删锁或备份 |
| 1004 | 维护条目属性查询失败，且非文件/路径不存在 | 与 1003 合并；权限/IO 故障会被描述成正在安装 | 改为明确“无法确认安装状态”，保留系统码，不绕过保护 |
| 1005 | OLE/COM 初始化失败 | 有原生提示，HRESULT 未展示 | 保留 HRESULT；卡重插无关 |
| 1006 | 命令行解析失败或显式开发参数形状不合法 | `packaged_deployment()` 异常返回 false；开发配置异常后被笼统捕获 | 明确解析失败，不把它当成合法开发部署 |
| 1101 | 系统原生架构不是 AMD64 | 有明确提示；当前没有完整 Windows 版本兼容性判定 | 使用受支持构建；不能把“支持范围 Windows 11”视为已执行 OS 版本检查 |
| 1102 | helper、创建器、格式化 DLL、厂商 DLL、HTML、JS 任一校验失败 | 预检可标记组件名称；原因可来自 2005～2008；主 EXE 不校验自身摘要 | 优先显示可取得的阶段码；本码为无细分信息的包检查失败，重装同版完整包 |
| 1103 | WebView2 版本查询失败、空版本或未安装 | 全部描述为未找到 Runtime，HRESULT 丢失 | 修复依赖；不能把查询失败直接断言为没有安装 |
| 1104 | VeraCrypt 驱动未加载、打开/查询失败 | catch-all 合并为不可访问，底层原因丢失 | 保留打开/查询错误；检查驱动或重启，不要求重插卡 |
| 1105 | 驱动可访问但接口版本不等于 0x126 | 明确不兼容 | 使用匹配依赖，不忽略版本保护 |
| 1106 | 启动检查自身异常、探针抛异常或返回非法状态 | 通用“检测失败/检查无法完成”；只展示第一个依赖失败 | 保留各独立检查结果及首个阻断项；不要把未执行检查记为通过 |
| 1107 | 已保存凭据缺失 | 预检使应用转到配置页，属可恢复引导，不一定显示错误页 | 等待显式配置，不自动认证；诊断中记引导原因而非卡损坏 |
| 1108 | 凭据存储拒绝访问、格式/版本/长度错误 | 同样转配置页；可有 2001～2003，部分未知错误仍被合并 | 有细分阶段优先细分；不要未经确认覆盖原凭据 |

预检只展示第一个依赖失败，并不意味着其他独立检查都成功；凭据格式正确也不意味着凭据与卡匹配。六类文件可能分别因不存在、权限、占用、路径别名、重解析、非固定盘、大小异常、摘要不同或哈希 API 错误失败，详见 2005～2008。

| 主码 | 条件/失败可能性 | 当前实现/诊断缺口 | 处理与边界 |
|---|---|---|---|

| 1205 | 子路径拼接/部署参数/摘要字符串解析失败 | 合并为初始化失败 | 区分发布配置错误与用户环境错误 |

| 1211 | 消息循环 `GetMessageW` 返回 -1 | 当前与退出消息一起结束循环，最后返回 0 | 区分消息循环故障和正常退出，记录系统码 |

| 1503 | HID 接口路径长度/终止符等结构非法 | 当前抛 runtime_error | 固定诊断描述，不记录设备路径或身份 |
| 1504 | 收到有效卡状态变化，但 `ExecuteScript` 提交/回调失败 | 已有原生“界面刷新失败”提示，HRESULT 未展示 | 状态以原生为准，重建界面；禁止以网页旧状态授权操作 |

非目标 VID/PID、非到达/移除事件、非法通知结构目前会被忽略，不为每个无关 USB 事件生成用户错误。首次失败后 presence 仍为“有卡”，重复 arrival 不重试；真实 removal 清空上下文，随后 arrival 才重新探测。未收到移除只能作为待核对事件缺口，不能直接给出某个已证实的系统故障码。

| 1405 | 初始/事件触发刷新中桥方法拒绝 | 多个 catch 合并成 unavailable | 保留调用成员编号与 HRESULT/固定拒绝原因 |
| 1406 | 已认证态的容器/操作结果数量或字段形状非法 | refreshNativeState 校验并抛异常；新进程首次未认证通常不走这部分 | 只记录契约失败，不导出容器名、路径、盘符、结果内容 |
| 1407 | 配置页凭据状态查询失败 | 页面按 unreadable 处理，不等于真实存储必然损坏 | 保留桥故障，等待用户处理，不自动重写凭据 |
| 1408 | 脚本解析、DOM 初始化、未捕获异常或 Promise 拒绝 | 顶层启动 IIFE 不能覆盖脚本执行前或其外全部错误 | 需最小页面就绪/异常捕获；无脚本执行时由原生就绪超时兜底 |

WebView 用户数据目录权限、文件占用、运行时安装不完整、安全软件干预等只是 1302～1305 的**候选原因**；没有 HRESULT/事件证据时不可直接定性。后台旧窗口 generation 不匹配时主动忽略回调属于正常生命周期行为，不应报错。

### 超时口径

`VikeyHelperBackendConfig` 默认 5 秒；`probe_vikey_helper_operation` 在 ResumeThread 成功后建立 deadline，响应读取、可选秘密载荷读取、退出等待共享该 deadline。**不是每一步各有 5 秒，也不是整个应用启动严格限时 5 秒。** 前面的校验/目录/进程准备和后面的清理不等价于该响应期限；同步请求写入没有被这里的循环统一变成全流程超时。不可只靠把 5 秒调大或自动重试来掩盖启动差异。

## 7. CardError 原因码完整表（无阶段时的主码）

这些原因 1～18 已存在于公共卡错误域。页面有 20xx 阶段码时，下面的原因作为独立数字字段保留；无阶段时才使用相应 30xx 主码。

|---|---|---|---|

| 2 | 3002 | 配置或输入形状不符合要求 | 区分保存格式、内部调用参数及响应矛盾，不能一律要求改 PIN |
| 3 | 3003 | 未找到设备 | 核对插卡与匹配条件；HID 可见不代表 SDK 已成功发现 |

| 10 | 3010 | 设备或 SDK 未细分故障 | 含返回值矛盾、身份变化、关闭会话失败等分支，需补阶段 |

## 9. 现有诊断链的具体缺口与实现顺序

1. **首先保存单次探测原始失败。** `CardEntryContextController::handle_arrival()` 和 `CardEntryRouter::route()` 吞异常；`VikeyHelperCardEnrollment` 又会把非卡域异常合并成 unexpected。应在信息丢失前转换为固定数字结构，仅留内存，不转发异常文本。
2. **补齐 SDK 阶段。** `set_api_key`、`user_login` 的通用失败未设置已存在的 sdk_key/sdk_pin；0 张/多张、锁定、权限结果不符、身份变化和会话关闭失败亦有无阶段出口。不能仅凭枚举定义声称这些阶段已可显示。
3. **原始失败和清理失败分别保存。** 当前 helper 客户端清理失败可覆盖原异常；只记录 cleanup 会掩盖首次启动的起因。
4. **补原生异步失败出口。** WebView 多处只返回 HRESULT；补 Native 错误兜底、NavigationCompleted、ProcessFailed 和页面就绪确认。注册安全选项失败仍中止，不降级。
5. **页面分类显示。** 无卡/待配置仍走正常页；界面桥错误不能统一声称卡故障。错误页用数字主码+中文原因+有限处理建议，不统一要求重插卡。
6. **只在已观测边界打点。** 单调耗时、步骤编号、结果码、是否提权、主进程工作目录是否等于安装目录、启动来源（未知也允许）、卡通知是否到达即可。启动来源若无显式可信标记不能通过父进程猜测为确定事实。
7. **保留验证边界。** 报错后拔卡能进入等待只证明移除到页面这条链有效；再次插卡仍可能重新探测失败。重启成功不证明之前一定是超时，也不证明卡记录绝对没有问题。

拟诊断事件字段：格式版本、会话内序号、启动以来毫秒、阶段/子步骤整数、结果整数、主码、reason、native_kind、native_code、cleanup_code。错误事件可关联固定组件角色编号，不能记录任意文本。默认内存有界缓冲，用户主动导出；显式诊断落盘需另行设计容量/清除规则。**不记录全部用户操作、密码/PIN/密钥、卡身份、卡内容、容器名/路径/盘符、挂载结果、档位或可以推出档位的信息。** 成功 IPC 的 detail 可能携带硬件身份，不能当作“数字就安全”直接记录。
