# 应用启动失败与数字错误码对照表

更新日期：2026-09-20。原始审计基线为 a0686c6，当前接入状态包含本轮页面精简与启动 TXT 日志；历史实现与验证记录见根目录 DEVELOPMENT_LOG.md。本文合并原错误码表与覆盖清单，作为唯一编号查询入口。

范围包括安装器拉起 EXE、前置检查、原生会话、WebView／页面就绪和首次卡探测。登录、建卷、挂载等运行期操作不扩展。

- **已接入**：已有实际失败出口和数字显示通路，不等于实机故障验证通过。模拟测试与待实机边界逐项保留在最后一列；未注明针对性模拟的项目仅完成源码审核和相关构建。
- **引导／合并／范围外**：正常引导、以更具体码代替、非首次启动路径或明确未实现。

共 121 个编号，109 项标记已接入、12 项属于其他分类；其中 32 项有针对性模拟验证，77 项已接线但待对应原生故障实机验证。尚未实现完整崩溃捕获及 SDK 主错／清理双错的跨 IPC 附码。首次安装启动问题仍未取得实机数字证据，不能将诊断接入称为根因已修复。

“全面”指当前主要失败出口及已知边界，不能枚举 Windows、驱动和第三方 SDK 的所有内部故障。阶段码只能证明失败位置，不能直接证明杀毒拦截、网络故障、卡损坏或密码错误。

## 1. 实际启动顺序

1. Windows/安装器/快捷方式启动主 EXE。进入 `wWinMain` 前失败时，应用无法显示自己的错误页。
2. 解析 EXE 所在目录，检查 `.usb-vault-update` 和 `.usb-vault-setup.lock`。存在或不能确认不存在，均拒绝启动。
3. `OleInitialize`；无显式开发参数时执行 `inspect_startup()`：系统架构、六类随包文件、WebView2、VeraCrypt 驱动、已保存凭据。
4. 前四项不通过则退出；凭据不就绪则进入配置页。**这一步不访问卡，也不验证保存的 PIN 是否正确。**
5. 注册/创建窗口，恢复窗口大小，注册拖放；拖放失败目前只告警，其他功能继续。
6. 固定页面文件；正常会话分支构造卷服务、卡适配器、入口/认证/界面控制器，注册 HID 通知并枚举已插入卡。
7. 有卡时立即执行一次 `handle_arrival()`：读取凭据 → 校验/准备 helper 与 SDK → 建立隔离进程与 IPC → SDK 认证并只读探测卡 → 校验响应/退出/清理 → 决定卡入口。
8. **步骤 7 在 WebView 初始化和主窗口显示之前同步执行。** 此处访问卡，错误 PIN 可能消耗卡的尝试次数。前置检查“不访问卡”不能扩展解释为整个应用启动不访问卡。
9. 异步创建 WebView 环境与控制器、配置安全选项、挂原生桥、导航本地页面；注册卡事件定时器并进入消息循环。
10. 页面读取启动视图、窗口预设、会话状态和活动会话。无卡/待初始化/待登录是正常结果；不可用或桥失败才是故障。配置页返回和真实拔出后重插会重新建立/探测入口。

安装完成页此前继承 TEMP，快捷方式此前指向已删除的事务暂存目录；`a0686c6` 已修正。**尚未证明该差异就是首次卡探测失败的根因。** helper 自身采用显式绝对路径、独立工作目录和裁剪后的环境，不宜只凭主进程工作目录推断 SDK 出错。

## 2. 数字码规则

- 页面保留状态标题，下方只显示红色“错误码：xxxx”，不显示原因／底层／清理附码，不提供复制入口；这些数值保存在启动日志中。`0000` 表示无错误，不把正常无卡或待配置计为故障。
- 主码分区：10xx 启动前/入口，11xx 前置检查，12xx 原生会话，13xx WebView，14xx 页面/桥，15xx 设备事件，20xx 已有诊断阶段，30xx 缺少阶段时的卡错误，40xx 入口/记录判定，90xx 未分类故障。
- 主码优先选择实际失败的、可证实的最具体阶段。已有 `DiagnosticStage = n` 映射到 `2000+n`，**不更改原有枚举或 helper 协议数值**。无阶段但存在 `CardError = n` 时用 `3000+n`。明确的本地步骤另用本表代码。
- 同时保留独立的数字字段：`reason`（现有 CardError 1～18，0 表示无可用卡错误）、`native_kind`（0 无、1 Win32、2 HRESULT、3 进程退出码）、`native_code`（无符号 32 位十进制）。类别不是卡错误时不得把同值的系统错误冒充 CardError。
- 示例：主码 **2019**、原因 **18**、底层类别 **0**、底层码 **0**，只表示等待辅助进程响应超时；不能解释为 PIN 错误或已经确认网络故障。底层码 0 在类别 0 时表示**未取得**，不是操作成功。
- HRESULT 如需内部十六进制转换，应在诊断工具中进行；用户页面及导出的编号仍用数字。未知阶段/原因不得误解成成功；本地归为 9001，非法 IPC 枚举仍按 2018 拒绝。
- 一个失败事件保留一个主码；主进程文件清理失败可另存首个附码，SDK 双错仍受 helper 单主诊断协议限制。
- 同一主码可覆盖技术上同类的多个失败出口，底层码与步骤编号用于进一步区分；实际接入与验证结论以每行对应列为准。

### 超时口径

`VikeyHelperBackendConfig` 默认 5 秒；`probe_vikey_helper_operation` 在 ResumeThread 成功后建立 deadline，响应读取、可选秘密载荷读取、退出等待共享该 deadline。**不是每一步各有 5 秒，也不是整个应用启动严格限时 5 秒。** 前面的校验/目录/进程准备和后面的清理不等价于该响应期限；同步请求写入没有被这里的循环统一变成全流程超时。不可只靠把 5 秒调大或自动重试来掩盖启动差异。

## 9. 字段与明确边界

- WebView 原生提示的事件类别：0 无可用事件细分，1 WebErrorStatus，2 ProcessFailedKind；事件码为 SDK 固定枚举整数，0 可能是合法枚举值，须结合类别判断。系统错误类别／码另存 HRESULT，不把事件枚举冒充系统错误。
- 1308 步骤 1–9：开发工具、默认菜单、脚本对话框、WebMessage、状态栏、快捷键、密码保存、自动填充、外部拖放。1316 步骤 1／2 为读取客户区／设置 Bounds；1313 步骤 1／2 为读取成功状态／读取导航错误。
- 页面启动脚本未开始执行／解析失败由 1315 原生就绪超时兜底；脚本已启动但就绪前出现 error 或未处理拒绝标记 1408。就绪后的所有业务异常不在本轮统一覆盖范围。
- 主进程可保留探测主错及首个文件清理附码；helper IPC 只支持一个主诊断，SDK 探测与 SDK 清理双错、失败打开时的析构清理没有单独跨进程附码。本轮不变更协议，不声明已解决此边界。
- 最外层和窗口过程的 C++ 异常兜底不等于崩溃捕获；入口前加载失败、系统强杀、栈损坏及无法分配任何 UI 资源时，不保证应用能显示错误。
- 已接入下述明文启动 TXT；没有全量操作记录、启动来源标记或复制／导出入口。相同主码不证明相同外部根因，首次启动问题仍待实机证据。

### 启动 TXT 格式与生命周期

每次启动在 `USB Vault.exe` 同目录创建 `startup-log-yyyyMMdd-HHmmss.txt`，采用本机时间；同秒重名追加 `-01` 至 `-99`，不覆盖旧文件。明文为 UTF-8 兼容的 ASCII 字段，不写凭据、异常原文、路径、卡身份、容器或档位。文件立即刷新，每份最多 128 条数值记录、小于 64 KiB；不自动删除旧日志，卸载也不专门删除这些未知文件。

字段：`seq` 为序号，`elapsed_ms` 为距日志开始的单调毫秒，`step` 为阶段，`outcome` 为 0 开始／1 完成／2 失败；`code/reason/native_kind/native_code` 与主诊断对应，`cleanup_*` 为首个附加文件清理诊断；`event_kind/event_code/substep` 为固定事件／子步骤编号。主诊断或清理诊断无有效错误码时，对应原因与底层字段清零，未带类别的底层值一律清零。成功 helper 响应中的身份字段从不送入日志。

阶段：1 入口、2 维护检查、3 OLE、4 前置检查、5 窗口、6 制品固定、7 原生会话／首次卡探测、8 WebView、9 页面就绪、10 错误、11 日志结束。阶段 4 子步骤 1–5 为系统、组件、WebView、驱动、凭据；阶段 8 子步骤可为 1305 控制器完成、1313 导航完成，失败时沿用错误码表的事件／步骤定义。日志结束记录的“完成”只表示结束记录，不表示前面没有错误。

就绪（包含显示卡错误或配置查询错误的可用页面）、WebView 致命失败或应用提前退出后关闭日志，不记录登录、挂载及后续拔插。主程序日志没有逐个 SDK 成功调用的耗时，只有首次探测整体耗时及失败阶段；不伪装成完整跨进程追踪。未能取得 EXE 目录或尚未进入应用入口时可能无法产生日志；达到记录上限时停止追加，运行期间不会改变认证次数。
