# P3.26 登录前破坏性重新初始化：开发切片计划

日期：2026-09-21。状态：用户已授权按片开发、验证及自主提交，最终完成全套审查。用户意图是忘记应用登录密码后执行与设置页初始化等价的破坏性重置，不是找回旧密码或重置厂商 PIN。

## 一、范围与明确后果

- 复用正式产品卡记录服务与双槽日志，只改用户区前 736 字节应用保留区。216 字节逻辑记录改为精确 provisioning marker，并完成旧槽覆盖、描述符归一化和复读验证。
- 两个密码信封一起废弃，不选择性改密，不保留旧根秘密。下次使用现有初始化流程生成新根秘密；即使输入相同密码，也不能靠新记录恢复旧容器。
- 不修改厂商 PIN、UserSN、API Key、厂商激活信息或保留区外字节；不删除容器文件、加密索引或其他本地配置。不得复用旧 P1 全用户区擦除工具。
- 仍须有效的厂商凭据和卡访问权限。2011 等后端不可用、PIN 错误、锁定或设备通信失败，不通过重置绕过，也不自动反复认证。
- 初版只接受当前版本、结构有效、已初始化的产品卡。未知版本、损坏日志、外来数据、多卡歧义均拒绝；已未初始化的卡进入现有初始化入口，不再次擦写。
- 此授权允许未登录但持卡且具备 SDK 凭据的人破坏旧访问能力；不能验证其是否为原应用密码持有人。双信封界面和结果不区分密码角色，不增加恢复或探测通道。
- 2026-09-21 用户明确决定：登录前重置不以 VeraCrypt 挂载状态为门禁；已有挂载卷、驱动挂载查询失败或状态不明均允许继续，不要求先卸载，也不自动卸载。仍须满足同卡确认、记录有效、SDK 访问权限和本应用操作互斥等独立条件。
- 未登录不代表全机无挂载，其他实例或 VeraCrypt 可能仍持有卷及旧密钥。重置不撤销这些已存在的访问，也不清除其他进程秘密；现有卷可能继续可用，卸载后不能凭新卡记录恢复旧访问能力。
- 成功后关闭应用，下次启动进入初始化页，与设置页现行行为一致。只承诺 SDK 可寻址区域的覆盖和复验，不承诺芯片物理安全擦除或清除外部副本。

## 二、需求冲突及实施顺序

需求清单 N-06／Q-02 与里程碑仍暂停忘记密码入口；P2.17g／17h 仅允许已认证的重新初始化。本计划不把旧限制默认为已取消：第 1 片需将本次单独评审的破坏性语义写成明确增补，保留历史说明，并同步里程碑。

技术真相以需求清单为准；本文件记录切片边界，实际进展写入原 DEVELOPMENT_LOG.md。用户于 2026-09-21 明确授权本功能按片自主提交：每片遵循审计→检查现有代码及测试→实现→验证及安全审查→汇报并提交，再进入下一片；禁止推送。

## 三、切片与验收

### 第 1 片：需求边界与原生确认状态

- 同步需求增补与里程碑，定义登录前重置为独立能力，保留设置页 can_reset_card_record 的已认证条件。
- 设计并实现易失的 prepare／cancel／confirm 状态契约；prepare 仅只读探测，不调用会归一化日志的 get_blob，不写卡。
- 原生状态保存同次插卡代次、期望硬件身份及单次确认关联，不把硬件 ID、记录或凭据交给网页。取消、拔卡、配置切换、窗口销毁及路由变化全部使其失效。
- 确认不得从页面直接提供任意硬件 ID 或写入目标；重复确认、过期确认、未 prepare、无卡及非登录路由均拒绝。
- 验证：状态机模拟覆盖以上失效条件；prepare／cancel 路径零写卡、无新增认证重试、无新本地痕迹。本片不开放页面入口或可执行重置。
- 完成标准：动作及确认契约可以独立验证，相关需求不再含相互矛盾的现行规则。

### 第 2 片：本应用操作互斥与重复执行保护

- 审阅主应用、配置切换、后台任务、卡事件与现有实例协调方式，建立由原生层持有的重置排他租约，不仅设置当前网页 busy 标记。
- 防止本应用对同卡同时登录、初始化、改写或重置；当前实例的后台操作与重置按现有互斥机制收束。租约不能以其他实例已登录、卷已挂载或驱动查询失败为拒绝理由，也不要求别的实例先清除既有认证会话。
- 登录前可用性、prepare 和 confirm 均不得依赖“无 VeraCrypt 挂载卷”的结果；挂载枚举仅用于可跳过的提示，查询失败不能阻断。检测到挂载卷时展示盘符与确认弹窗：红色“强制卸载”、普通“跳过”；只有用户明确点击才卸载所展示且身份仍匹配的目标，不自动扩大范围；未知状态允许跳过，不执行未知目标卸载。
- 当前实例任务冲突、同卡正在写入或不能取得独立操作互斥属于动作竞争，允许拒绝；不得把“可能有挂载卷”包装成互斥失败。外部软件仍可能保留旧密钥及访问，本功能不提供跨进程密钥撤销。
- 验证：挂载存在、没有挂载、查询失败和状态未知四种场景，在其他条件相同时具有相同的重置可用性及执行结果；验证跳过路径零卸载，强制卸载仅针对确认时展示且重新核验身份一致的目标，失败留在弹窗允许跳过；关闭取消本次重置。另测两个实例同卡写入竞争、重复确认、取消及异常释放租约。
- 完成标准：挂载状态不会阻挡登录前重置，同卡并发写入和重复执行受到原生约束；设置页原有认证与卸载行为保持不变。

### 第 3 片：登录前重置执行与写入恢复

- 增加入口控制器的独立重置方法，只有有效单次确认和排他租约才可调用；不删除原设置页的认证检查。
- 确认时重新只读核验，与 prepare 的插卡代次、硬件身份及产品记录状态匹配才构造短生命周期 update target。卡记录在准备后改变时拒绝，不重新绑定另一张卡继续执行。
- 复用正式双槽日志提交和 helper 写入（独立条件重置，不调用会归一化的准备阶段读取）；必要的记录一致性材料只保存在锁页易失内存，不新增持久身份或敏感日志。
- 单次消费执行权限；成功清除相关会话状态并请求关闭。写入开始后不承诺取消回滚，错误或结果不确定均退休上下文，不以页面重试自动重复写入。
- 只有新标记、旧槽清理及日志归一化得到复验才能报告完成；中断前后可能保留旧记录或已提交新标记，重新插卡时按真实日志状态识别，不假定全部成功或全部未写入。
- 验证：双信封失效、新初始化生成不同根秘密、未知／损坏记录拒绝、换卡零写、每一写阶段短写／报错／复读失败／清理中断；用保留区外哨兵证明仅 0～735 字节发生修改。
- 完成标准：无需旧应用密码即可完成受控重置，厂商配置和保留区外内容未改；不依赖真实卡即可充分验证失败路径。

### 第 4 片：受限桥接与窗口生命周期

- 提供登录前可用性、准备、取消、确认及完成结果的最小桥接口；严格校验参数、当前路由、确认代次和后台互斥，不提供任意记录写入或通用擦除接口。
- 复用现有后台执行机制处理可能阻塞的卡操作，保持窗口响应；UI 只接收中性状态，不接收 SDK 凭据、硬件身份或密码角色。
- 卡事件、配置切换、窗口关闭与执行完成回调按代次过滤；写入期间的关闭／拔卡转入明确收束，不把迟到结果投到新会话。
- 验证：桥参数错误、直接 confirm、重复调用、prepare 后换卡、后台占用、关闭与迟到回调；取消不写卡，成功才按既定策略关闭。
- 完成标准：从原生桥调用到卡记录执行形成受控闭环，尚不暴露页面按钮。

### 第 5 片：登录页忘记密码流程

- 登录页增加“忘记密码”入口；弹窗标题明确为“重新初始化安全卡”，说明旧卡记录废弃、容器文件保留和成功后关闭应用；说明重置不能撤销既有访问，旧容器无法凭重新初始化后的安全卡打开；按第五节显示可跳过的挂载提示，只有显式选择才强制卸载已展示且身份匹配的目标。
- 默认不勾选不可撤销确认，未确认不提交；关闭、取消或卡变更后清空确认状态，不保存浏览器状态。普通忘记密码操作不要求旧应用密码。
- 初始提示可复用设置页语义，但事件、状态与入口分开，不能借此扩大设置页接口权限。页面只读可用性查询不得触发额外探卡或 PIN 尝试。
- 无卡、卡后端不可用与不支持的记录给出可执行但不泄密的状态；已有挂载卷或无法查询挂载状态均不显示重置阻断提示。写入结果未知明确说明需重新插卡确认，不自动再次擦写。
- 验证：DOM 与原生桥集成覆盖两入口隔离、确认复位、重复点击、失败、换卡和成功关闭；视觉检查登录页及弹窗，文案不区分信封或容器角色。
- 完成标准：用户无需进入应用内部即可走完已审阅的破坏性流程；设置页行为无回归。

- 实机仅使用用户明确指定可破坏的测试卡和测试容器；分别验证未登录重置、区域外哨兵、SDK 凭据保持、拔卡／换卡、旧容器访问后果和新初始化。未获得测试介质授权时，保留为待验，不使用用户现有卡代替。

## 四、实现前重点复核

1. 用户已明确允许挂载存在及状态不明时重置。登录前动作不得复用设置页“先卸载、仍挂载则拒绝”的路径；不推断全机无卷，也不承诺撤销其他实例的旧密钥或已挂载访问。
2. 当前重置在执行时重新探测当下卡；新流程必须额外绑定用户确认时的那张卡，不能只依赖探测到写入期间的硬件 ID 校验。
3. 产品记录识别是结构及版本校验，不等于基于旧密码验证持有人身份；不能声称忘记密码流程仍保留原密码的授权强度。
4. 在记录服务层读卡可能触发日志恢复写入，因此确认之前只允许真正只读的 inspection 链。
5. 工作区另有 FAT32 容量开发，执行各片前复核差异，避免混入、覆盖或提交其他任务修改。

本功能已获准自主逐片提交；不能将授权视为六片已实现或已验收。

## 五、已确认挂载提示文案

标题：仍有容器处于挂载状态

检测到当前仍有处于挂载状态的容器，请确认是否需要在重置安全卡前卸载。

- 若这些容器属于本次重置的安全卡，请先保存文件、关闭相关程序，再点击“强制卸载”。
- 若这些容器与本次重置无关，或你希望保留当前挂载状态，请点击“跳过”，继续重置。

强制卸载可能导致未保存的数据丢失。重置后，旧容器将无法凭重新初始化后的安全卡打开。

按钮：红色“强制卸载”、普通“跳过”；附本次目标盘符。强制卸载成功后继续，失败允许跳过；关闭取消重置。该弹窗不替代最初的破坏性确认。
