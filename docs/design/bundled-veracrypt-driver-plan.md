# 安装包内置 VeraCrypt 驱动

## 范围与编号

2026-09-29 用户要求实施此前讨论的六片方案。本项统一归 P4.14 内置驱动改造（P4.14.1～P4.14.6），与已放弃的 P5 密码机制方案无关。目标是在 USB Vault 安装器内直接部署未修改的官方签名 x64 驱动，不再安装完整 VeraCrypt MSI 或 GUI；继续使用现有 IOCTL 和 VeraCryptFormat.dll。应用仍依赖 Windows 内核驱动，驱动部署需要提权。

## 已查明的代码与驱动契约

- 当前 tools/package-p2-development.ps1 固定 MSI 摘要、签名和上游提交；build-windows-installer.ps1 要求 MSI 载荷。后续改造不得只移除这一检查而不替换信任链。
- tools/setup_helper/main.cpp 已在 SCM 存在但驱动不可访问时拒绝重装；setup_policy.h 要求安装后复检。这两条门禁继续保留并加强。
- 固定上游 b48e31f5b47da7d41025e3f0e02751675e15005a 的 Common/Dlgcode.c::DoDriverInstall 使用 veracrypt 服务、SERVICE_KERNEL_DRIVER、SERVICE_SYSTEM_START 和 System32\drivers\veracrypt.sys。仅非系统加密的数据卷部署纳入本方案，不能接管系统加密的 BOOT_START 服务。
- 来源文件为该提交跟踪的 src/Release/Setup Files/veracrypt-x64.sys；版本 1.26.29.3，SHA-256 为 1F0C6DB3559D1356C38A1486A967CD90DB5E6202E433FEA1DFE510DDB884FFB6，微软硬件兼容签名证书指纹为 3847B761C2846DB72F61149176D09F9BB2D43E8A。正式打包仍须复验，不能仅按文件名或版本信任。
- 现有 ABI 查询 0x126 不足以独自决定文件可信或版本可替换；D2 需同时核验服务配置和文件。
- 使用 tools/audit-veracrypt-driver.ps1 -DriverPath <候选文件> 获取只读 JSON 证据。此脚本不部署也不加载驱动，不是生产提权安全边界，不能用它替代 D3 的句柄及目标路径校验。

## 隔离验证与安全边界

干净 Windows x64 虚拟机应先做快照，确认无 VC 服务、驱动文件和系统加密；部署上述原始字节，创建固定服务并加载，检查实际 IOCTL 版本，对一次性测试容器执行挂载／写入／读取核对／卸载，再重启复查。Secure Boot、HVCI 状态逐项记录，签名验证通过不代表内核一定允许加载。实验仅操作隔离测试卷，不以开发机已有安装冒充独立部署成功。

用户后续明确授权卸载本机 VC 并测试：先通过驱动只读查询确认无挂载卷、无系统加密，正常退出主应用及助手，再由用户完成官方卸载向导；确认服务、驱动文件及 VC 程序目录不存在后才执行独立部署。此授权仅用于本次实验，不扩展为产品自动覆盖共享驱动的权限。实验留存于 out/evidence/bundled-driver-d1，产品实现须另行完成安全部署与回滚，不能直接复用实验脚本。

无驱动改名、无二进制修改、无关闭签名强制或 Secure Boot。保留上游许可及第三方声明，继续交付所需源码／source-offer 材料；最终分发法律复核仍属于交付出口。驱动签名与应用／安装器签名是不同事项。本项不改变 R-03、8.6 或当前密码机制。
