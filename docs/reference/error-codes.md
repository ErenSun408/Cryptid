# USB Vault 错误码对照表

更新日期：2026-10-13。适用源码：`95ff295`，产品实现提交：`e1c8da4`。

覆盖正式应用、卡助手、创建助手、管理员会话、安装卸载及页面业务中的自定义错误码、已公开的结果状态和诊断步骤。Windows、WebView2 和第三方组件的原始错误码按原类别保留；本文列出项目使用的映射和常见排查码，不穷举外部组件的全部编号。测试夹具、`spike/` 实验、协议 magic、DISPID、进度百分比和内部布尔标记不属于产品错误码。

## 查询方法

先确认报错模块和字段名，再查编号。同一个数字可以属于不同的编号体系，例如安装结果 `22` 表示安装失败，驱动诊断步骤 `22` 表示启动驱动服务；创建错误 `3` 表示管理员授权取消，驱动错误 `3` 表示卷认证未通过。不能只凭数字判断原因。

| 记录项目 | 含义 |
|---|---|
| 模块和操作 | 安装、启动、登录、创建、挂载、目录浏览、备卡、重置等 |
| 主错误码或结果状态 | 必须保留字段名；状态为取消、暂停或等待时不计故障 |
| 诊断步骤及原因码 | 主码定位到的子步骤、卡错误类别或服务状态 |
| 底层类别及原始值 | Win32、HRESULT、驱动返回值或进程退出码；十进制和十六进制均可 |
| 版本和时间 | 应用或安装包版本、失败时间，用于关联同次操作日志 |

接入状态按以下口径填写：**已接入**表示当前代码存在返回或显示通路，不代表对应实机故障已经复现；**内部接入**表示值只在异常、协议或日志中使用；**条件接入**表示仅在指定操作或兼容边界触发；**保留／未接入**表示编号或映射存在，但当前没有对应独立输出。成功、引导、取消和暂停单独标注。

应用诊断的 `primary` 保存主错误，`cleanup` 可保存首个清理附错；清理失败不替换主错误。`reason` 只对 CardError 1–18 有效，`native_kind` 为 0 无、1 Win32、2 HRESULT、3 进程退出码。类别 0 的底层值 0 表示没有取得原始码，不是“系统调用成功”。卡助手 IPC 仍只携带一个主诊断，不能完整保留 SDK 主错和清理双错。

页面通常只显示主码或中文提示。测试包的应用日志位于应用目录 `logs/runtime-log-*.txt`，创建助手日志使用 `creator-log-*.txt`；日志按现有命名和分段规则生成。旧包可能仍使用根目录下的 `startup-log-*.txt`。当前程序在页面就绪后继续记录运行事件，不能按旧版说明认定日志已经结束。日志开关受构建和配置控制；未生成日志不等于操作成功。对外提供日志前，应去除凭据、口令、卡身份、卡内容和私人路径。

提权报告仅用于定位。父进程核对管道连接 PID、报告长度、真实退出码和字段范围；失败报告不会授权安装，成功仍由父进程重新探测确认。没有报告时不能补猜原始 Win32／HRESULT。

当前随包驱动为官方签名 x64 `1.26.29.3`，接口版本 `0x126`，SHA-256 为 `1F0C6DB3559D1356C38A1486A967CD90DB5E6202E433FEA1DFE510DDB884FFB6`。支持的固定服务名为 `veracrypt`，类型为 KERNEL_DRIVER，启动方式为 SYSTEM_START。标准文件位于系统目录的 `drivers\veracrypt.sys`；服务路径允许标准相对路径、对应系统绝对路径和 `\SystemRoot\System32\drivers\veracrypt.sys` 三种形式。BOOT_START 和非标准配置不自动接管。

可在故障电脑上收集以下只读结果，与失败提示中的步骤和原始码一起核对：

```powershell
sc.exe query veracrypt
sc.exe qc veracrypt
Get-FileHash -LiteralPath "$env:windir\System32\drivers\veracrypt.sys" -Algorithm SHA256
Get-AuthenticodeSignature -LiteralPath "$env:windir\System32\drivers\veracrypt.sys"
```

服务状态 1 为 STOPPED，2 为 START_PENDING，3 为 STOP_PENDING，4 为 RUNNING，5 为 CONTINUE_PENDING，6 为 PAUSE_PENDING，7 为 PAUSED。RUNNING 只说明服务运行，不能单独证明摘要、签名和接口版本都符合要求；服务 1060 加文件存在属于需人工核对的残留状态，不是“完全未安装”。

### BitLocker 结果

字段：`getPartitionBitLockerProgress` 返回 `phase,state,encrypted_percent`。phase 0 表示没有当前确认阶段，1 等待确认解密，2 等待 Windows 解密完成；三者都已接入。未启动操作时的 `0,0,0` 是空进度，不足以证明磁盘未加密。

| 有效查询 state | 含义及触发条件 | 排查方法 | 当前接入状态 |
|---|---|---|---|
| 0 | 已解密，encrypted_percent 必须为 0 | 继续身份和写前复验 | 正常结果，已接入 |
| 1 | 完全加密 | 按确认流程关闭 BitLocker，等待完成 | 已接入 |
| 2 | 正在加密 | 先在 Windows 中处理转换状态，再重新检查 | 已接入 |
| 3 | 正在解密 | 等待解密结束；取消等待不等于 Windows 停止解密 | 已接入 |
| 4 | 加密暂停 | 在 Windows 中确认恢复或处理方式 | 已接入 |
| 5 | 解密暂停 | 在 Windows 中恢复解密后重新检查 | 已接入 |
| 非法 state／百分比 | 状态超出 0–5、百分比超出 0–100，或已解密却仍有加密百分比 | 按查询失败处理，不能当作未加密 | 已接入拒绝；无独立产品主码 |

原地加密的内部 `InplaceResult` 为 0 暂停、1 完成、2 认证撤销、3 失败，转换为页面创建状态或创建错误后再展示。索引中的 `PartitionConversionState` 为 0 正常、1 状态不确定、2 已暂停，属于恢复元数据状态，不是错误主码；不确定状态不得当作可继续写入的确认。

### 登录页忘记密码重置

字段：`getLoginResetStatus`；状态与一次性票据、当前卡代次共同使用。

| 状态 | 含义及触发条件 | 排查方法 | 当前接入状态 |
|---|---|---|---|
| 0 | 空闲或已取消准备 | 需要时重新开始 | 正常状态，已接入 |
| 1 | 准备、强制卸载或重置执行中 | 等待结果，不重复提交 | 正常状态，已接入 |
| 2 | 准备完成，等待明确确认 | 核对风险说明及当前挂载事实；票据本身不是成功结果 | 已接入 |
| 3 | 准备或确认失败，结果未确认 | 停止重复写卡，重新检查当前卡和阶段；不能报告重置成功 | 已接入，无独立细分主码 |
| 4 | 重置前强制卸载失败 | 处理占用；是否跳过只能沿现有明确确认流程决定 | 已接入，无独立细分主码 |
| 5 | 重置已写入并复验完成 | 按结束流程关闭并重新建立卡入口 | 成功状态，已接入 |
| 6 | 票据过期、卡移除或卡代次失效 | 重新准备，不复用旧票据 | 已接入 |

### 新密码确认

来源：[confirmed_password.h](../../include/usb_vault/security/confirmed_password.h)。以下是原生确认拒绝原因，不是登录口令是否正确的判断。

| 原因 | 含义及触发条件 | 排查方法 | 当前接入状态 |
|---|---|---|---|
| 1 mismatch | 两次规范化后的新密码不一致 | 重新完成两次输入 | 内部接入；页面同时有本地确认提示 |
| 2 insufficient_strength | 密码策略不接受当前输入 | 按当前界面的输入要求调整 | 内部接入；不在日志中保存密码特征 |

密码强度反馈 0 rejected、1 acceptable、2 strong 是输入策略结果，不是故障编号。产品登录失败先看桥结果和当前卡诊断；部分失败只返回 E_FAIL，不能一律当作 PIN 错误。新密码确认原因也不能用于判断旧密码正确性。

### 配置凭据读取和保存

来源：[card_configuration_webview_host_object.h](../../include/usb_vault/ui/card_configuration_webview_host_object.h)。这两个字段分别编号，不能互相套用。

| 字段／值 | 含义及触发条件 | 排查方法 | 当前接入状态 |
|---|---|---|---|
| credential_status 0 | 当前凭据可读且格式有效 | 不代表已与实体卡匹配；显式访问卡后才能验证 | 正常结果，已接入 |
| credential_status 1 | 未保存完整凭据 | 完整填写并保存，不自动认证 | 引导状态，已接入 |
| credential_status 2 | 已存凭据读取失败或格式不可用 | 查凭据存储权限和格式，避免未经确认覆盖原值 | 已接入；配置页可显示 1108 |
| ConfigurationOutcome 0 | 整组保存及回读确认成功 | 按界面继续 | 成功结果，已接入 |
| ConfigurationOutcome 1 | 字段长度、字符集或组合格式无效 | 按界面字段要求核对，不提供真实凭据给排障人员 | 已接入 |
| ConfigurationOutcome 2 | 存储或保存后回读失败 | 查 Credential Manager 访问及系统错误；原值可能已被覆盖 | 已接入 |

备用卡的读取、目标预检、写入和复验复用 CardError 和 SDK 阶段，当前没有一套专属备卡数字码。原生弹窗以空白／非空白、连接变化和操作成功／失败提示进度；页面收到的关闭事件也不承载完整错误码。临时通信失败可按既有只读退避恢复，凭据、PIN、权限或多卡失败不因此自动重试。设置保存、列表索引读写和卡上记录重置的部分失败仍使用通用异常或中文提示，见[未统一编号的出口](#gaps)。

## COM 桥与进程退出

### 桥返回 HRESULT

以下列出页面桥显式返回的 HRESULT，并补充原生弹窗使用的 S_FALSE。拒绝调用与实际业务失败必须结合方法名区分；同一个 HRESULT 可以出现在多个模块。

| HRESULT | 含义及触发条件 | 排查方法 | 当前接入状态 |
|---|---|---|---|
| 0x00000000 S_OK | COM 调用成功返回 | 继续读取业务结果；不表示内部业务一定成功 | 已接入 |
| 0x00000001 S_FALSE | 备卡原生弹窗的继续条件未满足，阻止按钮关闭弹窗 | 按提示完成换卡和稳定连接；不是失败 HRESULT，也不是写卡成功 | 内部回调已接入；非页面桥错误 |
| 0x80004001 E_NOTIMPL | 不支持的 IDispatch 类型信息调用等 | 使用现有桥契约，不反射调用未提供能力 | 已接入 |
| 0x80004002 E_NOINTERFACE | 请求了对象不支持的接口 | 核对调用接口和对象版本 | 已接入 |
| 0x80004003 E_POINTER | 必需输出参数或对象指针为空 | 修正原生调用契约 | 已接入 |
| 0x80004005 E_FAIL | 业务异常或其他无法细分的桥失败 | 保留方法名、业务状态和同次日志；不能据此推断具体原因 | 已接入，多个模块共用 |
| 0x8000FFFF E_UNEXPECTED | 当前没有相应任务模式／结果，或对象状态不符合查询要求 | 核对调用顺序，重新建立有效任务 | 已接入 |
| 0x8000000A E_PENDING | 任务、卡事件或独占操作尚未结束 | 等待当前操作，不并发重试写操作 | 已接入 |
| 0x80070005 E_ACCESSDENIED | 未认证、卡代次失效、桥已退役、缺少授权或业务门禁拒绝 | 核对当前会话和调用顺序；不是一律要求全程序提权 | 已接入 |
| 0x8007000E E_OUTOFMEMORY | 字符串或对象分配失败 | 查系统资源和分配失败位置 | 已接入 |
| 0x80070057 E_INVALIDARG | 参数值、名称、索引或设置超出允许范围 | 核对参数契约 | 已接入 |
| 0x80020001 DISP_E_UNKNOWNINTERFACE | Invoke 使用非 IID_NULL 接口标识 | 修正 COM 调用接口标识 | 已接入 |
| 0x80020003 DISP_E_MEMBERNOTFOUND | 方法号不存在或当前桥没有该成员 | 核对页面与原生组件是否匹配 | 已接入 |
| 0x80020005 DISP_E_TYPEMISMATCH | 参数类型、形状或部分值不合法 | 核对字节数组、布尔、整数、字符串及参数顺序 | 已接入 |
| 0x80020006 DISP_E_UNKNOWNNAME | 名称查询不是已注册方法 | 核对桥方法名和应用版本 | 已接入 |
| 0x80020007 DISP_E_NONAMEDARGS | 页面事件上报传入命名参数 | 按 reportPageEvent 的三个位置参数调用，不传命名参数 | 已接入页面事件桥 |
| 0x8002000E DISP_E_BADPARAMCOUNT | 参数个数或命名参数不符合契约 | 核对参数个数及调用方式 | 已接入 |

`0x80004005` 也可能记录为无符号十进制 `2147500037` 或有符号十进制 `-2147467259`，三者是同一 32 位值。页面捕获到的任意异常数值只有在能确认来源类别时才能查询，不能直接套用 CardError 或 CreationError。

### 正式进程退出码

| 进程／退出码 | 含义及触发条件 | 排查方法 | 当前接入状态 |
|---|---|---|---|
| 主应用 0 | 正常退出，含部分窗口关闭路径 | 不代表所有历史业务成功；查相应结果和日志 | 已接入 |
| 主应用 1 | 启动检查、窗口创建或最外层失败后退出 | 查四位主码和原始错误 | 已接入 |
| 卡助手 0 | 响应已发送，响应中的 status 仍可能非零 | 必须同时读取响应 status、diagnostic 和 native_kind | 已接入 |
| 卡助手 2 | 外层解析、读取或响应处理异常，未能正常完成响应 | 查 2014／2018及协议和进程记录 | 已接入 |
| 创建助手 0 | 请求或会话正常结束 | 单次业务仍以有效协议结果和复检为准 | 已接入 |
| 创建助手 2 | 命令行、父进程号、nonce 或会话参数非法 | 使用成套主程序调用，不手工构造命令 | 已接入 |
| 创建助手 3 | 管道、安全描述符、所属进程或连接身份检查失败 | 查创建／管理员会话日志及下面的会话步骤 | 已接入 |
| 创建助手 4 | 未取得真实管理员权限 | 查管理员会话和令牌 | 已接入 |
| 创建助手 5 | 请求执行失败，已尝试发回 CreationError | 优先查看协议错误结果，再看进程退出码 | 已接入 |
| setup helper | 使用安装与卸载表中的 0、10–13、20–22、64 | 按模块和命令查询 | 已接入 |

管理员会话与创建助手共用 EXE，但使用不同入口。会话入口的步骤日志定位如下；失败返回 3，参数非法返回 2，父进程结束或会话管道正常结束可返回 0。

| 会话步骤 | 含义及触发条件 | 排查方法 | 当前接入状态 |
|---|---|---|---|
| 1 | 打开当前进程令牌失败 | 查原始 Win32 和进程权限 | 内部日志已接入 |
| 2 | 查询提权信息失败或实际未提权 | 核对 UAC 和令牌；逻辑未提权时日志 Win32 可能没有因果意义 | 内部日志已接入 |
| 3 | 打开原所属进程失败 | 核对所属进程是否退出及句柄权限 | 内部日志已接入 |
| 4 | 构造当前用户管道安全描述符失败 | 查用户令牌和安全描述符创建错误 | 内部日志已接入 |
| 5 | 创建一次性会话管道失败 | 查命名冲突及系统权限 | 内部日志已接入 |
| 6 | 等待管道连接时出现异常 | 查管道错误和进程存活状态 | 内部日志已接入 |
| 7 | 连接超时或连接者 PID 不等于所属进程 | 核对 60 秒连接期限、所属进程及客户端身份；不要解除 PID 校验 | 内部日志已接入 |
| 8 | 设置管道模式失败 | 查原始管道错误 | 内部日志已接入 |
| 9 | 获取自身 EXE 路径失败或截断 | 核对程序路径及系统返回值 | 内部日志已接入 |
| 10 | 发送会话就绪回复失败 | 查对端进程和管道状态 | 内部日志已接入 |
| 11 | 请求标识或 nonce 不合法 | 核对成套组件和请求生命周期 | 内部日志已接入 |

会话还会把启动业务助手和句柄移交失败的 Win32 原值放入回复；`ERROR_BUSY` 表示上一业务助手仍在运行。这些原值不再编成一套新主码。会话日志部分步骤在逻辑校验后读取 `GetLastError`，应先按步骤定位，不能将该值一律当成可靠的原始 API 错误。
