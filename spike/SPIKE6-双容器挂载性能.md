# Spike 6 — 双容器 + Argon2id 端到端耗时实测

> **日期**：2026-08-17
> **目的**：验证 P-002「认证到挂载 ≤5 秒」在 N-05 双容器架构 + Q-06 Argon2id 派生下是否成立
> **结论**：✅ **成立，但有一个硬前提** —— 挂载时**必须显式指定 PRF**。
> 不指定则模式 A 约 **8.9 秒**，直接爆表。
>
> 附带推翻一项此前写入设计的缓解手段（并行挂载），并订正一处 Spike 2 的记录。

## 一、环境与方法

| 项 | 值 |
|---|---|
| 系统 | Windows 11 Home 26200 |
| 驱动 | VeraCrypt 1.26.29，版本号 `0x126` |
| 容器 A | `test.hc` 100MB **普通卷**（模拟加密盘） |
| 容器 B | `hidden.hc` 200MB，外层 198MB / 隐藏卷 50MB（模拟隐藏盘容器） |
| 两容器 PRF | 均为 SHA-512（VeraCrypt 默认） |

产品内为进程内调用，无此开销，下文"折算"一列已扣除。

## 二、🔴 核心发现：PRF 自动探测是最大的性能杀手

`MOUNT_STRUCT.pkcs5_prf = 0` 表示让驱动**逐个试遍所有 PRF**。
`vcspike.c:406` 原本就是这么写的，Spike 1 的 1.42-1.47s 也是在这个前提下测的。

### 2.1 自动探测 vs 指定 SHA-512

| 场景 | 自动探测（中位） | 指定 PRF=SHA-512（中位） | 提速 |
|---|---|---|---|
| 容器 A（普通卷） | 1435 ms | **994 ms** | 1.4× |
| 容器 B（**隐藏卷**） | **6616 ms** | **1742 ms** | **3.8×** |
| 容器 B（外层卷，模式 B） | —— | **902 ms** | —— |
| 串行 A + B隐藏 | 8115 ms | **2607 ms** | 3.1× |
| 并行 A + B隐藏 | 8286 ms | **2554 ms** | 3.2× |

原始数据（ms）：

```
自动探测   A: 1316 1464 1362 1435 1453
           B: 6616 6490 6625 6609 6710
       串行: 8042 8313 8348 8060 8115
       并行: 7835 7847 8286 8458 8511

PRF=SHA512 A:  987 1008  992 1001  994
         B隐藏: 1780 1670 1795 1668 1742
         B外层:  872  995  885  967  902
       串行: 2657 2618 2570 2607 2498
       并行: 2604 2475 2389 2576 2554
```

### 2.2 为何隐藏卷尤其慢

挂载隐藏卷时驱动**先试标准卷头（必然失败），再试隐藏卷头**。
自动探测下，失败的那一轮要把所有 PRF 试一遍。逐 PRF 实测成本（`hidden.hc`，
失败项表示两个头都用该 PRF 试过）：

| PRF | ID | 耗时 | 结果 |
|---|---|---|---|
| SHA-512 | 1 | **1774 ms** | ✅ 挂载成功 |
| SHA-256 | 3 | 760 ms | 失败 |
| BLAKE2s | 4 | 2265 ms | 失败 |
| Whirlpool | 2 | 3507 ms | 失败 |
| **Streebog** | 5 | **9188 ms** | 失败 ← 最贵 |

**Streebog 单项就要 9.2 秒**，这是自动探测不可接受的根源。

### 2.3 落地要求

1. 🔴 **建卷时锁定单一 PRF（建议 SHA-512）并记录下来**
2. 🔴 **挂载时显式传入 `pkcs5_prf`，禁止使用 0（自动探测）**
3. 该字段与用户输入无关，可随容器元数据一起保存（**注意：不得记录任何能推断出隐藏卷存在的信息，见主文档 8.4**）

## 三、🔴 并行挂载无效 —— 原缓解手段作废

| | 串行（中位） | 并行（中位） | 收益 |
|---|---|---|---|
| 自动探测 | 8115 ms | 8286 ms | **负收益** |
| PRF=SHA-512 | 2607 ms | 2554 ms | **2%，噪声级** |

两个独立进程同时发起挂载，总墙钟与串行几乎一致 ——
**驱动的挂载路径是串行化的**，并行没有意义。

> **主文档需修正**：第七节排期与 P-01 修订中"必要时两个容器的挂载并行化"这条缓解手段
> **不成立，应删除**。真正有效的手段是指定 PRF（第二节）。

## 四、Argon2id 参数可行域

VeraCrypt 官方配置为 `ARGON2_NO_THREADS`，故 `p > 1` 时各 lane 串行执行 ——
实测 p=1 与 p=4 无显著差异，**并行度对耗时不起作用**，选 p=1 即可。

单位 ms，取 2 次最优值：

| m (MiB) | t | AVX2 | SSE2（保守） |
|---|---|---|---|
| 256 | 1 | 209 | 333 |
| 256 | 2 | 477 | 500 |
| 256 | 3 | 610 | 682 |
| 512 | 1 | 646 | 683 |
| **512** | **2** | **918** | **1036** |
| 512 | 3 | 1279 | 1418 |

**推荐参数：m=512 MiB, t=2, p=1** —— 保守（SSE2）路径约 **1.04 秒**，
符合"单次派生 0.5-1 秒"的设计目标，且内存成本远高于 Q-06 建议的下限 256MB。

## 五、五秒预算合成

按产品内进程内调用折算（挂载值已扣除 70ms 进程开销），
Argon2id 取 SSE2 保守值 1036 ms：

### 模式 A（正常登录，最坏路径）

| 环节 | 耗时 |
|---|---|
| Argon2id 派生（512MiB/t=2） | 1036 ms |
| 挂载容器 A（普通卷） | 924 ms |
| 挂载容器 B（**隐藏卷**） | 1672 ms |
| **小计** | **3632 ms** |
| **P-002 余量（读卡通信）** | **≈ 1368 ms** |

### 模式 B（胁迫登录）

| 环节 | 耗时 |
|---|---|
| Argon2id 派生 | 1036 ms |
| 挂载容器 A | 924 ms |
| 挂载容器 B（外层卷） | 832 ms |
| **小计** | **2792 ms** |
| **余量** | **≈ 2208 ms** |

### ❌ 若不指定 PRF（对照）

模式 A ≈ 1036 + 1365 + 6546 = **8947 ms**，**超预算 79%**。

## 六、附带发现：`volumeType` 的泄露特性（订正 Spike 2 记录）

实测三种挂载方式下 `GET_MOUNTED_VOLUMES` 返回的 `type`：

| 挂载方式 | 对应模式 | 报告的 type |
|---|---|---|
| 外层密码，**不开保护** | **模式 B（胁迫）** | **`0` 普通卷** |
| `mount-outer`，**开保护** | 模式 C（维护诱饵） | `2` 外层卷 |
| 隐藏卷密码 | 模式 A（正常） | `1` 隐藏卷 |

**订正**：主文档与 `README.md` 记的"外层卷密码挂载 → type=2"**不准确**。
`type=2` **仅在开启隐藏卷保护时出现**；模式 B 不开保护，驱动报告的是 `type=0`。

### ✅ 对否认性是利好

模式 B 下挂出的卷，在驱动属性中**与普通卷完全一致**，没有任何"这是外层卷"的痕迹。
这为主文档 8.4 的"不可区分性"又添一层保障 —— 且这一层由 VeraCrypt 驱动免费提供。

### ⚠️ 但模式 A 存在活体泄露

模式 A 下驱动明确报告 `type=1(隐藏卷)`，而 `GET_MOUNTED_VOLUMES` 的 IOCTL 是
`FILE_ANY_ACCESS`（见 R-02），**任何普通用户进程都能查询**。

即：**真实隐藏盘处于挂载状态时，同机任何程序都可看出"有一个隐藏卷正挂着"。**

- 影响有限：能到这一步说明对手已在活动系统上，数据本身也已暴露
- 但**强化了"拔卡即卸载"（《基本需求》第 3 条）的必要性** ——
  它不只是便利功能，而是否认性的一部分
- **产品要求**：进入胁迫场景前必须确保真实隐藏卷已卸载；
  卸载响应时间需按此定级（Spike 1 实测卸载仅 73-106 ms，余量充足）

## 七、结论汇总

| # | 结论 | 状态 |
|---|---|---|
| 1 | P-002「认证到挂载 ≤5 秒」在双容器 + Argon2id 下**成立**，模式 A 约 3.6s，余量 1.4s | ✅ |
| 2 | **前提：挂载必须显式指定 PRF**。不指定则 8.9s，超预算 79% | 🔴 硬要求 |
| 3 | **并行挂载无效**，原设计中的该缓解手段作废 | 🔴 需改文档 |
| 4 | Argon2id 推荐 **m=512MiB, t=2, p=1**（保守路径 1.04s）；`p` 无效果 | ✅ |
| 5 | 模式 B 挂出的卷报告 `type=0`，与普通卷不可区分 —— 否认性利好 | ✅ |
| 6 | 模式 A 挂载期间 `type=1` 对任意用户进程可见 —— 活体泄露，强化拔卡即卸载 | ⚠️ |
| 7 | Spike 2 记录的"外层密码 → type=2"不准确，已订正 | ✅ 已修正 |


```bat
:: Argon2 基准（需先 vcvars64）
set SRC=D:\Desktop\usb-vault\spike\_vcref\src
cl /nologo /O2 /DARGON2_NO_THREADS /I"%SRC%" /I"%SRC%\Crypto\Argon2\include" ^
   /arch:AVX2 /c "%SRC%\Crypto\Argon2\src\opt_avx2.c"
:: 其余 argon2.c / core.c / ref.c / blake2b.c / opt_sse2.c 常规编译后一并链接
```
