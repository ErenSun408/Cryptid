# 更新事务接入约束

这些文件目前是安装器的底层组件，产品向导尚未接入；不得只取消“禁止覆盖”提示就交付。

## 文件和路径

- 每个目标、暂存和备份文件名必须来自构建时固定清单；恢复记录不能携带路径或命令。保留用户文件，不递归删除应用目录。
- 集成层须核对安装登记和规范化原位置，为同一安装位置使用固定的事务目录与锁路径，拒绝改到另一个非空位置。
- 事务目录必须私有，且绑定创建它的完整包身份及文件清单。只有同一包的恢复代码可以解释它；不同包、无身份或未知条目必须保留现场并拒绝覆盖。
- 应用、暂存和备份必须在同一固定磁盘卷上；目录树禁止重解析点。调用 `UpdateGuardDirectory` 固定每一条所用父目录，包括嵌套的清单子目录，并将句柄持有到所有文件操作结束；失败也调用 `UpdateReleasePaths`。
- `UpdateAcquireLock` 只接受已固定目录中的保留锁路径，独占且关闭时删除。它拒绝已有条目，不主动清除冲突文件。集成层还需在安装、卸载和恢复入口共享锁约定，并处理断电后可能残留的锁条目；不得用不同的随机锁名规避冲突。
- 入口和实际修改前检查应用占用；仍需在集成层防止替换期间新启动应用。锁文件只互斥遵守协议的安装器，不等同于禁止应用启动。

## 持久记录与恢复顺序

1. 验证全部路径、清单、包身份及占用后，完整提取并验证暂存文件。四字节记录只表示文件原先存在／不存在及整个事务已提交，不能包含凭据、容器或档位信息。
2. 对每个编译期条目调用 `UpdateJournaledReplace`：排他创建意图记录，使用 write-through 写入并 `FlushFileBuffers`，然后移动旧文件到备份、移动新文件到目标。每个编号在同一进程中只使用一次。
3. 只有全部文件及注册／快捷方式状态成功后，才通过 `UpdateWriteMarker` 写全局提交标记（827741442）。此标记成功前不得清理任何旧文件备份。
4. 重启或失败处理先调用 `UpdateLoadCommit`。无标记进入回滚，有效提交标记进入备份清理；损坏标记停止全部恢复。随后逆序调用 `UpdateRecoverFile`。不要混用会删除新文件的旧 `UpdateRollback` 或无全局提交保护的 `UpdateCommit`。
5. 未提交时，新文件移回暂存，旧文件恢复到原位置；已提交时保留新文件并精确删除备份。意图记录最后删除，因此恢复再次中断后可重试。状态矛盾、文件占用或记录损坏保留现场并报错；无意图却存在备份同样拒绝。
6. 集成层确认全部条目与登记一致后，最后精确清理提交标记、包身份及空事务目录。底层恢复不枚举、不清理未知条目，也不解释其他构建的遗留产品文件。

`UpdateTestCheckpoint` 仅供测试构建注入 `TerminateProcess`，产品构建不得定义。已测试进程被强制终止后的恢复和恢复再次中断；没有模拟物理断电、磁盘损坏或硬件缓存失效，不能承诺此类事件下自动恢复一定成功。
